## 0. 摘要

本系统是一个本地部署、单用户使用的 A 股交易辅助系统。它以“木桶理论”组织五块可独立测试、独立替换的“板”：

1. 选股
2. 买点
3. 止损
4. 仓位管理
5. 止盈

五模块通过统一管线生成可解释的**交易计划（TradePlan）**。回测引擎与实盘任务共用同一条管线，只替换时钟和券商适配器，避免“回测一套、实盘另一套”的逻辑分叉。

选股采用**双模板切换**：

- **模板 A：主线趋势回踩**——中期为主，适合日线、T+1 和人工执行；
- **模板 B：情绪龙头**——短线为主，只在情绪启动/发酵期启用；
- 两套模板共享“市场情绪环境层 + 主线行业层 + 龙头个股层”，按情绪周期和趋势状态切换。

系统每个交易日收盘后自动运行，生成次日候选池、交易计划和每日报告；也支持在看板或命令行手动触发。v1 由用户人工下单，系统只做决策辅助与持仓跟踪，不做任何自动委托。

**关键决策记录**

| 决策项 | 结论 |

## 1. 背景、目标与非目标

### 1.1 木桶理论的含义

交易结果由最弱的一块板决定。一个选股很准但止损失控、或买点很好但仓位过重的系统，长期结果依然会被短板拖垮。因此本系统的设计重点不是把某一模块做得极其复杂，而是：

- 五块板都有**明确的输入、输出和失败条件**；
- 每块板都能**独立测试、独立回测、独立替换**；
- 系统能通过回测消融和实盘归因，**指出当前最弱的是哪块板**；
- 任何一块板的规则变化都有**版本记录**，可追溯、可对比。

### 1.2 目标

1. 每个交易日收盘后自动产出候选池和次日交易计划。
2. 每张交易计划包含入场条件、止损、目标仓位、止盈规则和失效条件，且可解释。
3. 回测与实盘使用同一套五模块管线和同一份领域模型。
4. 能够跟踪实际成交、持仓、移动止损和计划执行偏差。
5. 选股策略可由用户独立替换，而不影响其余四个模块。
6. 通过“短板诊断”定位策略失效主要来自哪个模块。
7. 选股具备情绪周期、主线行业和龙头识别能力，并能在 A/B 两套模板间按规则切换。

### 1.3 非目标（v1 明确不做）

- **不自动下单**。所有买卖由用户人工执行。
- 不做多用户、SaaS、账户体系或权限管理（仅单用户登录）。
- 不做美股、港股、加密货币、期货。
- 不做基本面选股、新闻情绪、龙虎榜、北向资金等因子作为默认核心（v1 先做量价、情绪、行业和龙头；后续可扩展）。
- 不做盘中高频或分钟级自动交易。
- 不承诺任何收益，也不把默认选股规则包装成投资建议。
- 不做移动端 App（Web 看板移动端适配即可）。

### 1.4 成功标准

- 十年历史数据可稳定回补，每日增量同步可重复执行且结果一致。
- 同一配置、同一数据版本、同一代码版本的回测结果可完全复现。
- 五模块均有单元测试和契约测试；关键不变量（T+1、整手、现金非负、仓位上限）有自动化验证。
- 每日任务在交易日收盘后自动完成，失败可告警、可重试。
- 用户可以在看板完成“看计划 → 确认 → 录入成交 → 跟踪持仓 → 记录退出 → 复盘”的完整闭环。
- 替换选股策略后，其余模块和回测框架无需修改。
- A、B 两套模板可以分别回测、分别归因，也能在统一风控下切换。

### 1.5 合规与风险声明

本系统是个人研究与交易纪律工具，不构成投资建议。历史回测不代表未来收益。数据使用受 Tushare 授权条款约束，仅限个人研究，不得再分发。用户对自己的交易决策和资金安全负责。

## 2. 使用场景与用户流程

### 2.1 盘后自动运行

每个交易日 17:00（Asia/Shanghai，可配置）：

1. 检查交易日历，非交易日跳过。
2. 增量同步行情与基础数据。
3. 执行数据质量闸门。
4. 计算市场趋势、宽度、情绪周期，更新市场环境。
5. 计算行业强度、龙头分和候选池。
6. 运行选股 → 买点 → 止损 → 仓位 → 止盈 → 风控。
7. 落库并生成每日报告。

### 2.2 手动触发

用户在看板点击“立即运行”，或在命令行执行任务命令，可以：

- 指定交易日重跑；
- 只跑选股，或跑完整管线；
- 在数据修正后强制覆盖当天结果；
- 指定只跑模板 A、只跑模板 B，或双模板。

### 2.3 次日执行

用户在报告中查看：

- 市场环境：趋势档、情绪阶段、风险系数、A/B 模板是否可用；
- 主线行业和龙头排名；
- 候选池及入选理由；
- 每张计划的模板标签、触发价、止损价、目标仓位、止盈目标和失效条件；
- 当前持仓的止损上移、目标触发和风险预警。

用户按计划在券商端人工挂单或盯盘。成交后在看板确认计划并录入成交，系统开始跟踪持仓。

### 2.4 持仓管理

- 系统每天更新移动止损、时间止损和止盈目标。
- 看板提示“接近止损”“触及止盈目标”“计划失效”“情绪阶段切换”“持仓与计划偏离”等事件。
- 用户录入卖出成交后，系统计算已实现 R、盈亏和复盘标签。

### 2.5 回测与策略迭代

- 用户在“回测实验室”选择模板（A / B / 双模板）、策略版本、时间段和参数，运行回测。
- 查看资金曲线、回撤、分年度表现、分情绪阶段表现、交易明细和五模块诊断。
- 替换选股策略后，用同一时间段对比新旧版本的差异。

## 3. 系统架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────────┐
│  展示层：Web 看板（今日决策 / 持仓 / 回测 / 复盘 / 设置）      │
├──────────────────────────────────────────────────────────────┤
│  应用层：每日任务、手动触发、报告生成、成交跟踪、告警           │
├──────────────────────────────────────────────────────────────┤
│  决策层：市场环境层 + 五模块管线 + 横切风控（RiskGovernor）    │
│    环境层 → 选股 → 买点 → 止损 → 仓位 → 止盈 → 风控            │
├──────────────────────────────────────────────────────────────┤
│  领域层：MarketRegime / Candidate / TradePlan / Position 等    │
├──────────────────────────────────────────────────────────────┤
│  数据层：Tushare 同步、Parquet/DuckDB 行情、SQLite 业务状态    │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 五模块与执行顺序

用户最初把五模块表述为“选股 → 仓位管理 → 买点 → 止损 → 止盈”。系统保留这五个模块，但实际执行顺序调整为：

```
市场环境层 → 选股 → 买点 → 止损 → 仓位管理 → 止盈 → 风控
```

两个关键说明：

1. **环境层是共享上下文，不是第六块板。** 它计算趋势档、情绪阶段、风险系数和模板可用性，供选股、仓位和风控共同使用。
2. **仓位必须由买点和止损反推。** 若先定仓位再定止损，单笔风险会随止损距离漂移。统一采用固定风险法：

```
目标股数 = 账户风险预算 ÷ 每股风险
```

因此买点和止损必须先确定，仓位才能计算。止损与止盈共同定义 R，仓位使用初始 R，移动止损则影响持仓期间的风险敞口。

### 3.3 模块契约

所有模块都是确定性纯函数，依赖通过上下文显式传入，不在模块内部读数据库、不发网络请求。

| 模块 | 输入 | 输出 | 主要失败条件 |
|---|---|---|---|
| 环境层 RegimeService | 指数日线、全市场行情、涨跌停/连板/炸板数据、交易日历 | `MarketRegime`（趋势档、情绪阶段、风险系数、模板可用性、指标快照、行业强度） | 数据闸门未通过；情绪指标缺失；指数数据缺失 |
| 选股 Screener | `MarketRegime`、股票池、行业强度、龙头分、策略配置 | `Candidate[]`（模板 A/B、评分、理由、特征、行业、龙头排名） | 无候选；环境防守；模板不可用 |
| 买点 EntryPlanner | Candidate、`MarketRegime`、日线 | `EntryPlan`（A 回踩区间 / B 分歧低吸或回踩确认、触发价、有效期、失效条件） | 价格过度延伸；无有效触发结构；一字板 |
| 止损 StopPlanner | EntryPlan、日线、ATR、结构位、模板 | `StopPlan`（初始止损、距离、R、时间止损、移动规则） | 止损距离 > 8%（A）；B 止损结构无效 |
| 仓位 PositionSizer | EntryPlan、StopPlan、`MarketRegime`、AccountState、组合状态 | `PositionPlan`（股数、市值、风险金额、模板、约束检查） | 名额/风险/现金/行业/相关性不满足 |
| 止盈 TakeProfitPlanner | EntryPlan、StopPlan、结构阻力、模板 | `TakeProfitPlan`（A 分批目标 / B 短线目标、移动规则、时间退出） | 最近阻力位 < 1.5R（A） |
| 风控 RiskGovernor | 全部计划、账户、`MarketRegime` | `RiskDecision`（通过/降档/拒绝 + 理由） | 组合风险、回撤熔断、模板不可用、数据版本不一致 |

### 3.4 TradePlan 状态机

```
                 ┌──────────┐
                 │  DRAFT   │  管线生成
                 └────┬─────┘
         风控拒绝      │ 风控通过
        ┌─────────────┴─────────────┐
        ▼                           ▼
  ┌──────────┐              ┌────────────────┐
  │ REJECTED │              │ PENDING_ENTRY  │
  └──────────┘              └───┬────┬───┬───┘
                        成交      │    │   │ 过期/失效/环境转防守
                                  ▼    │   ▼
                            ┌────────┐ │ ┌───────────┐
                            │  OPEN  │ │ │ EXPIRED / │
                            └───┬────┘ │ │ CANCELLED │
                      全部退出    │      │ └───────────┘
                                ▼      │
                            ┌────────┐ │
                            │ CLOSED │ │
                            └────────┘ │
                                       │
                         （PENDING_ENTRY 不会直接到 CLOSED）
```

状态说明：

| 状态 | 含义 | 进入条件 |
|---|---|---|
| `DRAFT` | 管线已生成，尚未风控 | 五模块完成 |
| `REJECTED` | 风控拒绝 | 任一硬约束不满足 |
| `PENDING_ENTRY` | 已批准，等待触发 | 风控通过 |
| `OPEN` | 已成交持仓 | 用户录入成交或回测撮合成功 |
| `CLOSED` | 已全部退出 | 止损/止盈/时间/人工全部退出 |
| `EXPIRED` | 超过有效期未触发 | 有效期结束 |
| `CANCELLED` | 条件失效、环境转防守、模板不可用或用户取消 | 失效条件触发 |

持仓的分批止盈不改变 TradePlan 的 `OPEN` 状态；仓位数量与已实现盈亏记录在 Position / Execution 上。

### 3.5 横切风控 RiskGovernor

风控不属于五块“板”，而是对所有计划做最终组合级审查：

- 市场环境是否转为防守，或情绪阶段是否不再允许该模板；
- 当前回撤是否触发熔断；
- 持仓数量、行业集中度、相关性；
- 组合总风险（heat）是否超限；
- 现金保留、总仓位；
- 数据版本是否与计划一致；
- 是否存在重复计划；
- 计划本身的 R:R、止损距离是否满足下限。

输出三种结果：`APPROVE`、`REDUCE`（降低股数）、`REJECT`，并给出可读理由。

### 3.6 回测与实盘同源

- 回测和实盘调用同一个 `TradingPipeline.run(as_of, account, config)`。
- 差异只通过两个接口注入：
  - `Clock`：回测用历史日期，实盘用当前交易日；
  - `BrokerAdapter`：回测用模拟撮合，实盘用人工录入/CSV/券商只读接口。
- 环境层、选股、买点、止损、仓位、止盈、风控在回测和实盘中执行完全相同的规则。
- 模块内部禁止读取“今天之后”的任何数据；禁止在模块内直接访问数据库或网络。
- 每个信号和计划都记录 `data_version`、`strategy_version`、`code_version`，保证可复现。

### 3.7 短板诊断

系统不输出一个模糊的“综合分”，而是分别度量五块板，并给出证据：

| 模块 | 诊断指标（示例） |
|---|---|
| 选股 | 候选命中率、A/B 模板分别达到 +2R 的比例、候选池与市场基准的超额、行业/龙头命中率 |
| 买点 | 计划触发率、未触发原因分布、入场滑点、追高放弃率、触发后 3 日表现 |
| 止损 | 实际亏损 / 计划 R、止损后价格回归比例、跳空损失、时间止损占比 |
| 仓位 | 风险预算使用率、heat 触顶次数、集中度、实际仓位与目标仓位偏差、A/B 名额分配 |
| 止盈 | 已实现 R / 最大有利波动（MFE）、退出效率、分批止盈贡献、利润回吐比例 |

额外诊断：

- **情绪阶段判断质量**：阶段切换后次日市场表现、阶段与实际赚钱效应的偏差。
- **模板归因**：A 与 B 分别的收益、回撤、胜率、盈亏比、换手率、容量。
- **环境层贡献**：在防守/冰点/退潮期是否真的减少了亏损；在发酵期是否错过机会。

回测中支持**消融对比**：把某模块替换为基线或关闭，比较收益、回撤、盈亏比的变化，定位短板。实盘中按周/月生成同样的归因报告。

### 4.2 关键定义

- **R**：`R = 入场价 - 初始止损价`（每股风险金额）。所有盈亏以 R 的倍数表达。
- **趋势档**：进攻/中性/防守。由指数相对 MA20/MA60 和全市场宽度决定。
- **情绪阶段**：冰点/启动/发酵/高潮/退潮。由涨停/跌停家数、最高连板、晋级率、炸板率、昨日涨停红盘率等合成判定。
- **风险系数**：`min(情绪系数, 趋势上限)`，用于缩放单笔风险预算。
- **组合总风险（heat）**：已持仓的 `Σ max(0, 当前价 - 当前止损) × 持仓股数 / 权益`，加上已批准未成交计划的 `Σ (计划入场价 - 止损价) × 计划股数 / 权益`。上限 7.5%。
- **回撤**：`1 - 当前权益 / 历史峰值权益`。
- **龙头分**：个股在所属行业内的综合排名分，由相对强度、量能、距高点、连板/首板、市值/价格适配等构成。
- **策略版本**：选股配置与五模块参数的规范化 JSON 哈希，例如 `sv_ab12cd34`。
- **数据版本**：每日数据清单（行数、校验和、最后交易日）的哈希，例如 `dv_20261024_9f3c`。
- **候选**：选股模块的输出，不等于买入建议；只有通过买点、止损、仓位、止盈和风控后，才成为 `PENDING_ENTRY` 的交易计划。

## 5. 五模块规则（v1 默认基线）

> 以下参数均为默认值，存放在 YAML 配置中，可通过回测校准。选股部分是可替换的默认基线，不是系统强加的投资逻辑。

### 5.1 选股模块：三层 + 双模板

#### 5.1.1 总体结构

选股分成三层，仍然通过同一个 `ScreenerStrategy` 接口输出 `Candidate[]`：

```
环境层：趋势 + 宽度 + 情绪周期
   ↓ 决定：做不做、风险系数、A/B 是否可用
方向层：行业/主题强度
   ↓ 决定：只做最强 2–3 个方向
个股层：龙头分
   ↓ 决定：每个方向只做最强 1–2 只
```

- 环境层和方向层默认由 `RegimeService` 预计算，作为共享上下文传入选股、仓位和风控。
- 个股层由选股策略实现；自定义选股策略可以忽略或替换方向层，只要输出 `Candidate`。
- 两套模板 A/B 共享环境层和方向层，但个股条件和买卖规则不同。
- 默认策略版本：`dual_template_v1`。
- 用户可以用自己的选股策略整体替换；其余四模块只依赖 `Candidate` 契约，不依赖具体规则。

#### 5.1.2 环境层：市场情绪周期

**输入指标（每日收盘后计算）：**

- 趋势：中证全指（000985.CSI，缺失时回退沪深 300 000300.SH）相对 MA20、MA60；MA20 近 10 日斜率。
- 宽度：全市场可交易股票（上市满 120 日、非 ST、非停牌）中，收盘价 > MA20 的比例。
- 情绪：
  - 涨停家数、跌停家数；
  - 最高连板高度；
  - 连板晋级率（昨日 N 板今日晋级 N+1 板的比例）；
  - 炸板率（触及涨停但收盘未封住的比例）；
  - 昨日涨停今日红盘率 / 平均溢价；
  - 涨停成交额占比（可选）。

**情绪阶段判定（初始阈值，回测校准）：**

| 阶段 | 初始条件 | 情绪系数 | 模板 A | 模板 B |
|---|---|---|---|---|
| 冰点 | 涨停 <30；（跌停 >20 或 炸板率 >40%）；最高连板 ≤2；昨日涨停红盘率 <30% | 0 | 只观察 | 只观察 |
| 启动 | 涨停 30–60；最高连板 3–4；炸板率 20–35%；红盘率 40–55% | 0.5 | 可做 0.5× | 可做 0.5×，最多 1 只 |
| 发酵 | 涨停 >60；最高连板 ≥5；炸板率 <25%；红盘率 >55% | 1.0 | 可做 1.0× | 可做 1.0×，最多 2 只 |
| 高潮 | 涨停 >90；最高连板 ≥6；红盘率 >70%；但炸板率开始上升/昨日涨停溢价下降 | 0.5 | 仅回踩 0.5× | 不新开 |
| 退潮 | 涨停 <40；跌停 >30；炸板率 >45%；最高连板下降；红盘率 <30% | 0 | 不新开 | 不新开 |

**指标定义：**

- 涨停/跌停家数：按 `stk_limit` 判定，收盘价等于涨停价/跌停价。
- 最高连板：连续涨停的最大天数。
- 晋级率：昨日 N 板今日晋级 N+1 板的数量 / 昨日 N 板数量。
- 炸板率：触及涨停但收盘未封住的数量 / 触及涨停数量。
- 红盘率：昨日涨停股票今日收盘高于昨日收盘的比例。
- 昨日涨停平均溢价：昨日涨停股票今日开盘相对昨日收盘的平均涨幅。
- “炸板率开始上升/溢价下降”指：炸板率较前 3 日均值上升 ≥5 个百分点，或昨日涨停平均溢价较前 3 日均值下降 ≥1 个百分点；“最高连板下降”指最高连板较前 3 日均值下降。
- 前 3 日均值在历史数据不足时，使用当前可用的历史样本计算。

**判定规则：**

- 对每个阶段统计满足的条件数，取满足数最多的阶段。
- 若最高满足数 <2，则维持上一阶段；若并列，按 `退潮 > 冰点 > 高潮 > 发酵 > 启动` 的防守优先顺序。
- 表中“或”表示同一条件内的替代判定；例如冰点的“跌停 >20 或炸板率 >40%”只算一个条件。
- **阶段需连续 2 个交易日确认才切换**，避免一天一变。
- 首次运行或历史数据不足时，默认使用“启动”阶段，并在报告中标注“初始阶段”。
- 指标冲突时，取更防守的阶段。
- 上表中的风险系数和模板可用性是情绪层的结果；最终可用性和风险系数还需与趋势档叠加，以 5.1.7 为准。
- 环境数据缺失或质量不通过时，不生成新计划。

**趋势档与最终风险系数：**

| 趋势档 | 条件 | 趋势上限 |
|---|---|---|
| 进攻 | 指数 > MA20 且宽度 ≥55% | 1.0 |
| 中性 | 不满足进攻，也不满足防守 | 0.5 |
| 防守 | 指数 < MA60 或宽度 <35% | 0 |

- 判定顺序：先防守，再进攻，其余中性；例如指数在 MA20 与 MA60 之间时，即使宽度 ≥55%，仍按防守处理（因为指数 < MA60）。
- 最终风险系数 = `min(情绪系数, 趋势上限)`。
- 防守状态优先于情绪：即使情绪阶段为发酵，趋势防守也不新开仓。
- 阶段切换后的动作：
  - 转冰点/退潮：取消所有未成交计划；存量持仓止损上移到成本价/MA5，反弹不创新高减仓；B 持仓按 5.5.2 立即退出。
  - 转高潮：取消未成交的 B 计划；A 只保留回踩型，不追突破。
  - 转启动/发酵：按新阶段恢复对应模板和风险系数。
- 阶段只影响次日及之后的计划；当日已成交持仓按原有止损/止盈规则管理。

#### 5.1.3 方向层：只做主线

**行业强度评分（0–100）：**

- 20 日行业涨幅百分位：30%
- 5 日行业涨幅百分位：20%
- 行业宽度（成分股 > MA20 的比例）：20%
- 行业成交额/换手变化：15%
- 行业涨停数占比：15%

**规则：**

- 取强度排名前 2–3 个行业。
- 要求连续 2 个交易日在排名前列，避免一日游行情。
- 少于 5 只可交易股票的行业不参与排名。
- 主线 = 最强且持续的行业；模板 A 可在前 2–3 个行业中选股，模板 B 只做前 1–2 个主线。
- 数据优先使用申万行业指数/成分股（含历史成分）；不可用时用 `stock_basic.industry` 聚合，报告标注“行业分类降级”，并提示可能的分类偏差。
- 行业强度只使用 T 日及以前的数据，T+1 才可用于交易。

#### 5.1.4 个股层：龙头分

**龙头分（0–100），在行业内排名：**

- 20 日相对强度（个股 20 日涨幅在行业内的百分位）：25%
- 5 日相对强度（个股 5 日涨幅在行业内的百分位）：15%
- 成交额与换手率：20%
- 距 60 日高点距离（越近越好）：15%
- 连板/首板/涨停状态：15%
- 市值与股价适配：10%

**规则：**

- 每个行业只取龙头分前 2 名进入候选。
- 跟风票排除：
  - 行业内龙头分排名 >3；
  - 成交额明显弱于龙头（例如低于龙头 50%）；
  - 涨停时间明显靠后（有 `limit_list_d` 时）；
  - 行业启动后被动补涨，而非率先启动。
- 候选必须携带：模板标签 `A/B`、行业、龙头排名、龙头分、情绪阶段、入选理由和关键特征值。
- 相同分数按 `ts_code` 排序，保证回测可复现。

#### 5.1.5 模板 A：主线趋势回踩

**适用环境：** 启动/发酵/高潮；高潮期仅回踩、风险系数 0.5×。

**基础股票池（硬性过滤）：**

- 沪深主板 + 创业板；科创板、北交所默认关闭，可按交易权限开启。
- 上市满 120 个交易日。
- 剔除 ST / *ST / 退市整理股票（按 `namechange` 的时点状态判断）。
- 剔除停牌股票。
- 20 日平均成交额 ≥ 1 亿元。
- 股价 ≥ 3 元。
- 信号日收盘涨停或一字板的不纳入（次日难以成交）。

**个股条件：**

- 所属行业为强度前 2–3，且行业强度持续。
- 龙头分行业前 2。
- `收盘 > MA20 > MA60`，MA20 近 10 日向上。
- 20 日涨幅的全市场百分位处于前 30%。
- 收盘价 ≥ 60 日最高价的 90%（距高点不超过 10%，强势但未必要突破）。
- 回调 3–8 个交易日，5 日均量 < 20 日均量（缩量）。
- 收盘价贴近 MA10 或 MA20（±2%），且未跌破 MA20。
- 企稳 K 线：收盘 > 开盘，或下影线长度 ≥ 实体长度，或收盘位于当日振幅上半区，或次日放量确认。
- 流通市值 50–500 亿元；股价 5–100 元。

**输出：** 每个行业最多 2 只，按 A 综合分排序；全市场最多 15 只 A 候选。

- A 综合分 = 龙头分 × 70% + 回踩形态分 × 30%；回踩形态分由缩量程度、距 MA10/MA20 距离、回调天数、企稳 K 线构成。

#### 5.1.6 模板 B：情绪龙头

**适用环境：** 仅启动/发酵；高潮、冰点、退潮不新开。

**基础条件：**

- 主线行业前 1–2；行业内有至少 3 只涨停，或行业昨日涨停股今日红盘率 ≥50%。
- 炸板率 <35%，最高连板高度 ≥3。
- 个股为行业龙头/最强票，龙头分行业前 1–2。
- 首板或二板；二板必须是板块内最强/最早上板（有 `limit_list_d` 时用 `first_time`，否则用连板高度和成交额近似）。
- 量能 ≥2 倍 20 日均量；换手率 5%–20%。
- 流通市值 50–200 亿元；股价 5–50 元。
- 非 ST；无一字板；v1 只做 ST/停牌/涨跌停/一字板等基础过滤，减持、质押、立案等事件数据后续接入。
- 避开：4 板以上、20 日涨幅 >80%、高位炸板/天地板、明显跟风票。

**输出：** 每个主线最多 2 只，按 B 综合分排序；全市场最多 8 只 B 候选；实际开仓受 B 名额上限约束。

- B 综合分 = 龙头分 × 70% + 板型/情绪分 × 30%；板型/情绪分由连板高度、首板时间、封单/量能、板块地位构成。

#### 5.1.7 A/B 切换规则

| 情绪阶段 | 趋势档 | 模板 A | 模板 B | 最终风险系数 |
|---|---|---|---|---|
| 冰点 | 任意 | 只观察 | 只观察 | 0 |
| 启动 | 进攻/中性 | 可做，0.5× | 可做，0.5×，最多 1 只 | 0.5 |
| 发酵 | 进攻 | 可做，1.0× | 可做，1.0×，最多 2 只 | 1.0 |
| 发酵 | 中性 | 可做，0.5× | 可做，0.5×，最多 1 只 | 0.5 |
| 高潮 | 任意 | 仅回踩，0.5× | 不新开 | 0.5 |
| 退潮 | 任意 | 不新开 | 不新开 | 0 |
| 任意 | 防守 | 不新开 | 不新开 | 0 |

- 阶段切换有 2 日确认；确认后的阶段用于下一交易日。
- 趋势防守的优先级高于情绪阶段。
- 阶段切换时，未成交计划按新阶段处理；转冰点/退潮取消全部未成交计划；转高潮取消未成交 B。
- 已成交持仓不因阶段切换立即清仓，但执行 5.1.2 的止损收紧规则。

#### 5.1.8 可替换性与失败处理

- 选股实现遵循 `ScreenerStrategy` 协议：
  ```text
  generate(as_of, regime, universe, features, config) -> list[Candidate]
  ```
- 其余四模块只依赖 `Candidate` 字段，不依赖选股内部规则。
- 每个选股策略有独立名称和版本号，存于 `configs/strategies/`。
- 用户后续提供自己的选股规则时，可以新增策略文件并切换，不需要改管线、回测或看板。
- 数据质量闸门失败：不生成候选，任务标记失败并告警。
- 防守/冰点/退潮：候选可以生成用于观察，但不进入买点/仓位流程；报告中标注“仅观察”。
- 候选为空：正常结束，报告说明原因（过滤后数量、环境状态、行业强度）。
- 模板 B 数据降级（缺少 `limit_list_d` 或行业成分数据）：B 候选标记“数据降级”，默认降低优先级或按配置禁用。

### 5.2 买点模块

买点不是预测，而是**带条件的执行指令**。所有计划在信号日收盘后生成，最早次一交易日执行。

#### 5.2.1 模板 A：主线趋势回踩

- 入场区间：MA20 ± 2%。自定义策略如果输出短期回踩候选，可使用 MA10 ± 1.5%。
- 挂单方式：限价单挂在区间中点。
- 成交条件：次日最低价 ≤ 限价；成交价 `min(次日开盘价, 限价) + 滑点`。
- 不追高：
  - 若次日开盘价高于区间上沿 3% 以上，当日放弃，计划作废。
  - 若入场价 > MA20 × 1.08，直接拒绝（价格过度延伸）。
- 失效条件：
  - 收盘价跌破区间下沿；
  - 收盘价跌破 MA20；
  - 次日开盘价低于区间下沿 3% 以上（跳空破位）。
- 有效期：3 个交易日。

#### 5.2.2 模板 B：情绪龙头

- **B1 分歧低吸**：涨停次日低开或回踩 MA5–MA10，量能收缩，分时企稳后买入。
  - 日线近似：在 MA5–MA10 区间挂限价单，次日最低价触及且收盘未跌破区间下沿则视为成交。
  - 若有分钟数据，增加“分时企稳”确认；v1 不依赖分钟数据，按日线近似并在回测中保守处理。
- **B2 回踩确认**：首板/二板后回踩 MA5，缩量，次日放量收阳或重新站上 MA5 时买入。
- 不追高：次日开盘高于前收盘 3% 以上不买。
- 一字板、全天封死涨停、停牌：不买。
- 失效条件：跌破 5% 止损位、跌破 MA5/MA10 且不能收回、情绪阶段转退潮、板块炸板率骤升。
- 有效期：2 个交易日。

#### 5.2.3 通用规则

- 触发前若收盘价跌破初始止损价，计划取消。
- 市场环境转为防守、情绪阶段转冰点/退潮、或模板不再可用时，所有未成交计划取消。
- 次日涨停无法买入、停牌无法成交，按回测/实盘规则处理。
- A 股 T+1：买入当日不能卖出，计划必须考虑隔夜风险。
- v1 不依赖盘中分钟数据；用户可在券商端设置条件单。盘中实时提醒作为后续扩展（见第 14 节）。

### 5.3 止损模块

止损的任务是定义“这笔交易在什么情况下证明我错了”。

#### 5.3.1 初始止损（A/B 通用结构，参数不同）

1. 取结构支撑位候选：
   - 模板 A：近 10 日最低价、突破平台下沿、MA20（仅当 MA20 低于入场价时）；
   - 模板 B：近 5 日最低价、MA5/MA10（仅当均线低于入场价时）、首板/二板当天的开盘价或涨停价。
2. 剔除高于或等于入场价的候选，取剩余候选中的最高者作为支撑位。
3. 若有支撑位：`结构止损 = 支撑位 - 0.5 × ATR14`；若没有支撑位：`结构止损 = 入场价 - 1.5 × ATR14`。
4. 若结构止损 ≥ 入场价，改用 `入场价 - 1.5 × ATR14`。
5. 计算止损距离 `d = (入场价 - 结构止损) / 入场价`。
6. 模板约束：
   - A：`d > 8%` 放弃；`d < 3%` 放宽到 3%；`3% ≤ d ≤ 8%` 使用结构止损。
   - B：止损距离默认不超过 5%；若结构止损距离 >5%，改用 `入场价 × (1 - 5%)`；若 <3%，放宽到 3%。
7. 价格四舍五入到 0.01；`R = 入场价 - 初始止损`。

#### 5.3.2 时间止损

- A：持有满 10 个交易日，若未达到 +1R 且收盘价低于入场价，退出。
- B：持有满 3 个交易日，若未创新高，退出；若情绪阶段转退潮，立即退出。
- 时间止损按收盘价成交，次一交易日执行（遵守 T+1）。

#### 5.3.3 移动止损

- 浮盈达到 +1R：止损上移到入场价 + 往返成本（保本）。
- A：浮盈达到 +2R，止损上移到 +1R；之后每个交易日 `新止损 = max(前一日止损, 收盘价 - 1.5 × ATR14)`。
- B：浮盈达到 +2R，止损上移到 +1R；之后 `新止损 = max(前一日止损, 收盘价 - 1.5 × ATR14, MA5)`。
- 止损只升不降。
- 若价格跳空穿越止损，按实际可成交价退出，不假设在止损价精确成交。
- 买入当日即使触及止损也不能卖出（T+1），最早次一交易日按开盘价或可成交价退出。

### 5.4 仓位管理模块

采用固定风险法 + 组合级顺序分配，模板 A/B 使用不同的风险预算。

#### 5.4.1 计算公式

```text
风险金额   = 权益 × 模板风险比例 × 环境系数 × 回撤系数
每股风险   = (入场价 - 止损价) + 往返成本估算
目标股数   = floor(风险金额 / 每股风险 / 100) × 100
```

- 往返成本估算约为入场价的 0.3%（佣金、印花税、过户费、滑点综合）。
- 目标股数不足 100 股则放弃。
- 计算后再依次通过单票、现金、总仓位、heat、行业、相关性约束，必要时降档或拒绝。

#### 5.4.2 激进档默认参数

| 参数 | 模板 A | 模板 B |
|---|---|---|
| 单笔风险比例 | 2.5% | 2.0% |
| 单模板持仓上限 | 3 只 | 2 只 |
| 止损距离 | 3%–8% | 3%–5%（默认 5%） |
| 时间止损 | 10 个交易日 | 3 个交易日 |
| 单票市值上限 | 权益的 40% | 权益的 40% |

组合级参数（A/B 共用）：

| 参数 | 默认值 |
|---|---|
| 同时持仓上限 | 3 只（含已批准未成交计划） |
| 总仓位上限 | 100% |
| 最低现金保留 | 权益的 10% |
| 组合总风险 heat 上限 | 7.5% |
| 同一一级行业上限 | 2 只（含未成交计划） |
| 相关性上限 | 与已持仓或已批准计划的 60 日收益相关性 >0.8 时，只保留评分更高者 |
| 环境系数 | 由 `MarketRegime.risk_factor` 决定，范围 0–1 |
| 回撤系数 | 回撤 ≥10% 时 0.5；≥15% 时 0，暂停新开仓 |

#### 5.4.3 组合级分配

- 同一天有多个计划通过风控时，按“模板优先级 + 选股评分”依次分配名额和风险预算。
- 模板优先级默认：启动期 B 优先（最多 1 只），A 补充；发酵期 A 与 B 同权；高潮期仅 A；具体可配置。
- 名额、heat、现金或行业约束用尽后，剩余计划标记为 `REJECTED`，理由为“组合容量不足”，而不是静默丢弃。
- 同一只股票当天只允许一张计划。
- 已批准未成交的计划占用名额和 heat，防止重复超配。
- B 模板最多占 2 个名额；A+B 合计不超过 3 个名额。

#### 5.4.4 回撤熔断

- 权益从峰值回撤 ≥10%：单笔风险系数降为 0.5。
- 回撤 ≥15%：暂停所有新开仓，只管理存量持仓；恢复需人工在看板确认。
- 回撤恢复到 5% 以下时，10% 档的降档自动解除；15% 档必须人工重启。

#### 5.4.5 A 股交易约束

- 股数按 100 股整手。
- 买入当日不可卖出（T+1）。
- 佣金万 2.5（最低 5 元）；卖出印花税 0.05%；过户费 0.001%；滑点默认 0.1%–0.2% 单边。
- 停牌、涨停买不到、跌停卖不出，均按不可成交处理。

### 5.5 止盈模块

#### 5.5.1 模板 A

按 R 倍数分批，结合结构阻力，不采用固定百分比止盈。

| 阶段 | 动作 |
|---|---|
| +1R | 止损上移到保本（含成本） |
| +2R | 卖出 1/3，剩余仓位止损上移到 +1R |
| +3R 或最近主要阻力位 | 再卖出 1/3 |
| 剩余 1/3 | 趋势仓，按移动止损持有 |
| 时间退出 | 10 个交易日未到 +1R 且收盘低于入场价，全部退出 |
| 动量退出 | 达到 +2R 后，短期连续 2 日收盘 < MA10，或中期连续 2 日收盘 < MA20，退出剩余仓位 |

- 移动止损：`max(前一日止损, 收盘价 - 1.5 × ATR14, MA10 或 MA20)`，按候选周期选择均线。
- 盈亏比下限：若上方存在最近主要阻力位且其距入场价不足 1.5R，放弃该计划；若上方无明显阻力，按 R 目标执行。
- 分批股数按 100 股整手向下取整；若持仓不足 300 股，简化为在 +3R 一次性卖出，避免碎股。

#### 5.5.2 模板 B

| 阶段 | 动作 |
|---|---|
| +1R | 止损上移到保本 |
| +2R | 卖出 1/2 |
| 剩余 1/2 | 按 MA5 / 1.5×ATR 移动止盈 |
| 情绪退出 | 情绪阶段转退潮、板块炸板率骤升、龙头炸板/跌停，立即退出 |
| 时间退出 | 3 个交易日未创新高，退出 |

- 不设固定百分比止盈；以 R 和情绪/均线为准。
- 若持仓不足 200 股，+2R 时一次性卖出，避免碎股。
- 同日既触及止损又触及止盈：一律按止损先成交（保守假设）。

#### 5.5.3 通用规则

- 分批退出后，剩余仓位的止损继续按上表执行，只升不降。
- 所有退出都要遵守 T+1：买入当日不能卖出，最早次一交易日执行。
- 跳空穿越止损/止盈时按实际可成交价处理。

### 5.7 算例

**模板 A 算例**

账户权益 100 万元，进攻环境，发酵期，无回撤降档：

- 单笔风险金额 = 1,000,000 × 2.5% × 1.0 = 25,000 元。
- 入场价 20.00 元，初始止损 18.60 元（距离 7%）。
- 每股价格风险 = 1.40 元；往返成本约 0.06 元；每股风险 = 1.46 元。
- 目标股数 = floor(25,000 / 1.46 / 100) × 100 = 17,100 股。
- 持仓市值 = 342,000 元，占权益 34.2%，低于 40% 上限。
- R = 1.40 元；+2R = 22.80 元，卖出 1/3；+3R = 24.20 元，再卖出 1/3；剩余按移动止损持有。
- 若三笔计划同时通过，组合 heat 上限 7.5% 会限制总风险；名额上限 3 只。

**模板 B 算例**

账户权益 100 万元，发酵期，B 可用：

- 单笔风险金额 = 1,000,000 × 2.0% × 1.0 = 20,000 元。
- 入场价 10.00 元，止损 9.50 元（距离 5%）。
- 每股价格风险 = 0.50 元；往返成本约 0.03 元；每股风险 = 0.53 元。
- 目标股数 = floor(20,000 / 0.53 / 100) × 100 = 37,700 股。
- 持仓市值 = 377,000 元，占权益 37.7%，低于 40% 上限。
- R = 0.50 元；+2R = 11.00 元，卖出 1/2；剩余按 MA5/1.5ATR 移动止损，情绪转退潮立即退出。
- 若同一天还有 A 候选，A/B 合计最多 3 只，B 最多 2 只。

## 6. 数据层

### 6.1 数据源与接口

- 数据源：Tushare Pro，token 存放于 `.env`，不写入代码、不提交仓库、不出现在日志中。
- v1 使用的接口：
  - `stock_basic`：股票列表、上市/退市日期、市场板块
  - `trade_cal`：交易日历
  - `daily`：未复权日线（开高低收、成交量、成交额）
  - `adj_factor`：复权因子
  - `daily_basic`：换手率、流通市值等辅助字段
  - `stk_limit`：涨跌停价
  - `suspend_d`：停牌信息
  - `namechange`：历史名称变更（ST 判断）
  - `index_daily`：基准指数日线
  - `limit_list_d`：涨跌停列表（首板时间、开板次数、封单额等；B 模板优先）
  - `index_classify` / `index_member` / `sw_daily`：申万行业分类、成分股和行业日线（方向层优先）
- **权限预检**：M1 首先探测 token 对各接口的权限和频率限制。缺失权限时给出明确提示，并用规则推导降级：
  - 涨跌停价：按前收盘价和板块/ST 规则推导；
  - 停牌：成交量/成交额为 0 视为停牌；
  - ST：用 `namechange` 的时点名称判断；若不可用则明确标注数据降级，不静默忽略；
  - 炸板率：用 `high == 涨停价 且 close < 涨停价` 近似；
  - 晋级率：用连续涨停状态近似；
  - 首板时间：不可得时，B 模板标记“数据降级”，默认降低优先级或禁用；
  - 行业分类：用 `stock_basic.industry` 聚合，标记分类偏差风险。
- 若关键接口（`daily`、`adj_factor`、`trade_cal`、`stock_basic`）不可用，任务启动时直接失败并提示，不生成信号。

### 6.2 存储

| 数据类型 | 存储 | 说明 |
|---|---|---|
| 原始接口响应 | Parquet（`data/raw/`，按接口和日期分区） | 不可变，便于回溯和重放 |
| 清洗后行情 | Parquet（`data/processed/`，按年份分区） | 统一字段、类型和主键 |
| 环境/情绪/行业快照 | Parquet（`data/regime/`，按交易日分区） | 每日阶段、指标、行业强度、龙头排名 |
| 查询引擎 | DuckDB | 直接查询 Parquet，支持全市场向量化计算 |
| 业务状态 | SQLite（`data/app.db`） | 账户、持仓、计划、信号、任务、回测元数据 |
| 报告 | `reports/YYYY-MM-DD/` | HTML + Markdown |
| 回测产物 | `data/backtests/<run_id>/` | 指标 JSON、交易明细、曲线数据 |

选择理由：单用户本地部署，SQLite 零运维；Parquet + DuckDB 适合多年全市场扫描，避免把海量行情塞进事务库。后续需要多用户或并发写入时，可将业务状态迁移到 PostgreSQL，领域层和仓储接口不变。

### 6.3 同步与回补

- 首次回补默认从 2018-01-01 开始，可配置。
- 每日增量只拉取缺失的交易日，并回补最近 5 个交易日以捕获数据修正；以 `trade_date` 为幂等键，重复运行覆盖同一分区。
- 限流：按 token 权限配置每分钟请求数；失败指数退避重试；记录断点，支持续传。
- 同步顺序：交易日历 → 股票列表 → 日线 → 复权因子 → 每日指标 → 涨跌停/停牌 → 名称变更 → 涨跌停列表 → 行业分类/成分/行业日线 → 指数。
- 每天同步完成后生成数据清单（manifest），记录行数、校验和、最后交易日。

### 6.4 时点正确性（避免未来函数）

- 股票池使用**当日**的上市/退市/ST/停牌状态，不使用今天的股票列表回看历史。
- 回测包含已退市股票；退市前按最后可交易价格处理。
- 财务、市值等字段（若后续启用）必须使用公告日，不使用报告期回填。
- 行业成分股必须使用历史成分；若只能用当前行业分类，必须标记为“分类降级”，并在回测报告中提示潜在偏差。
- 情绪指标（涨停/跌停/连板/炸板/晋级）只使用 T 日收盘及以前数据；T 日收盘计算，T+1 才可用于交易。
- 所有特征只使用 T 日及以前的数据；T 日收盘生成的计划，T+1 才能成交。
- 自动化测试：将数据截断到 T 日计算信号，与全量数据在 T 日的信号必须完全一致。

### 6.5 复权与价格

- 指标和收益计算使用**后复权**序列，避免除权缺口造成假信号，也避免前复权随未来分红变化而重写历史。
- 真实成交、涨跌停、费用和止损价格使用**当日未复权价格**。
- 通过 `adj_factor` 在两种价格之间换算。
- 除权日调整持仓数量和现金分红；回测和实盘跟踪都遵循同一规则。
- 配股、缩股等复杂公司行为 v1 不支持自动处理，检测到后标记人工处理，并在报告中提示。

### 6.6 数据质量闸门

每日任务在生成信号前执行以下检查，任一致命项失败则中止并告警：

| 检查项 | 默认阈值 | 级别 |
|---|---|---|
| 预期交易日缺失 | 0 天 | 致命 |
| 当日股票覆盖率 | ≥99% | 致命 |
| 重复主键 `(ts_code, trade_date)` | 0 行 | 致命 |
| OHLC 关系违规 | 0 行 | 致命 |
| 复权因子为空或 ≤0 | 0 行 | 致命 |
| 成交量/成交额为负 | 0 行 | 致命 |
| 涨跌停价一致性 | 异常 ≤0.1%；超过 0.1% 致命 | 致命（阈值可配） |
| 情绪指标完整性 | 涨停/跌停/连板/炸板/红盘率均非空 | B 启用时禁用 B、A 继续；A-only 时警告 |
| 行业映射覆盖率 | ≥95% 通过；90%–95% 警告并降级；<90% 致命 | 致命（阈值可配） |
| 最新交易日新鲜度 | 收盘后应为最近已收盘交易日 | 致命 |

- 阈值全部可配置。
- 质量闸门失败时，系统不生成候选和计划，看板显示数据异常原因。
- 数据降级（如涨跌停接口、`limit_list_d`、行业成分不可用）必须在报告中显式标注，不能静默使用推导值。
- B 模板在情绪指标或行业分类降级时，默认降低优先级或禁用；是否启用由配置决定。

### 6.7 数据版本与可复现

- 每个交易日的数据清单包含：交易日、各接口行数、文件校验和、生成时间、环境/情绪/行业快照版本。
- `data_version` 为清单内容的哈希。
- 信号、计划、回测结果都记录 `data_version`、`strategy_version`、`code_version`。
- 回测可按 `data_version` 重建当时的输入快照；原始 Parquet 不可变，保证可重放。

### 6.8 备份与保留

- SQLite 每日自动备份到 `data/backups/`，保留最近 30 天。
- 原始行情 Parquet 长期保留；清洗数据可由原始数据重建。
- 报告和回测产物按需保留，默认保留最近 2 年。
- `.env`、`data/`、`reports/` 不提交 git。

## 7. 回测引擎

### 7.1 执行模型

回测逐交易日推进，每个交易日按以下顺序执行：

1. 用当日行情更新已有持仓：检查跳空止损、移动止损、止盈目标、时间止损。
2. 处理前一日及更早生成的待成交计划（T+1 起才可成交）。当日新成交的持仓受 T+1 限制，当日只记录成交和次日退出标记，止损/止盈检查从次一交易日开始。
3. 用当日收盘数据计算 `MarketRegime`（趋势、宽度、情绪阶段、行业强度）。
4. 用当日收盘数据运行选股管线，生成新计划（A/B/双模板按配置）。
5. 运行风控，更新账户、持仓和待成交计划。
6. 记录当日权益、持仓、风险、情绪阶段、模板可用性和计划状态。

### 7.2 成交假设（保守口径）

| 场景 | 成交规则 |
|---|---|
| A 限价买入 | 次日最低价 ≤ 限价才成交；成交价 `min(开盘价, 限价) + 滑点` |
| B1 分歧低吸（日线近似） | 次日最低价触及 MA5–MA10 区间且收盘未跌破区间下沿；成交价按区间中点或 `min(开盘价, 限价)` 保守处理 |
| B2 回踩确认 | 次日放量收阳/站上 MA5 才成交；成交价按收盘价 + 滑点（保守） |
| 次日高开 > 区间上沿 3% | 放弃，计划作废 |
| 涨停买入 | 开盘价即涨停或全天一字涨停视为无法成交；若盘中开板后触发，按触发价 + 滑点成交 |
| 跌停卖出 | 开盘价即跌停或全天一字跌停视为无法成交，顺延至下一可成交日；否则按止损价或开盘价成交 |
| 停牌 | 不成交 |
| 同日止损与止盈都触及 | 按止损先成交 |
| 买入当日触及止损 | T+1 限制，最早次日退出，按次日可成交价计算 |
| 跳空穿越止损 | 按开盘价或实际可成交价退出，不按止损价成交 |

- 回测不允许使用 T 日收盘价成交 T 日的信号。
- 撮合以日线 OHLC 为准；v1 不模拟盘中路径，因此采用对策略不利的假设。
- B 模板如果缺少`limit_list_d`、分钟数据或行业成分，必须在回测报告中标注“数据降级”，并单独列出结果。

### 7.3 费用与滑点

- 买入：佣金 0.025%（最低 5 元）+ 过户费 0.001% + 滑点。
- 卖出：佣金 0.025%（最低 5 元）+ 印花税 0.05% + 过户费 0.001% + 滑点。
- 滑点默认 0.1% 单边，可配置 0.1%–0.2%；B 模板因短线换手高，建议默认 0.2%，可配置。
- 分批止盈逐笔计算费用。
- 回测报告单列“费用拖累”，避免高换手策略虚高收益。

### 7.4 股票池与退市

- 每日按历史时点重建可交易股票池。
- 包含已退市股票；退市前最后一个可交易日按可成交价清仓，并记录“退市退出”。退市整理期可能连续跌停，回测仍可能低估实际损失，报告中需标注该局限。
- 长期停牌股票在停牌期间不可交易，复牌后按规则处理。
- 不使用当前指数成分股回看历史（避免成分股幸存者偏差）。
- 行业成分股优先使用历史成分；不可用时标记分类降级。

### 7.5 回测指标

- 收益：累计收益、年化收益、分年度收益、分市场环境/情绪阶段收益。
- 风险：最大回撤、回撤持续时间、波动率、下行波动率。
- 风险调整：Sharpe、Sortino、Calmar。
- 交易质量：胜率、盈亏比、期望 R、平均盈利 R、平均亏损 R、最大连续亏损。
- 执行质量：触发率、成交率、滑点、费用拖累、换手率、平均持仓天数。
- 模板归因：A-only、B-only、双模板分别的收益、回撤、胜率、盈亏比、换手、容量。
- 环境归因：不同情绪阶段、不同趋势档的表现；防守/冰点/退潮期是否减少亏损。
- 行业/龙头归因：行业强度分层、龙头分分层的绩效；龙头 vs 跟风票对比。
- 消融：环境层、行业层、龙头层分别关闭或替换后的绩效变化。

### 7.6 过拟合控制

- **滚动样本外（walk-forward）**：默认 3 年训练 / 1 年测试，滚动推进；参数只在训练段选择，测试段不调参。
- **参数敏感性**：对关键参数（止损距离、风险比例、评分阈值、情绪阶段阈值）做网格或单变量敏感性分析，观察绩效是否稳定。
- **消融对比**：逐模块替换为基线或关闭，判断收益来源和短板。
- **多市场环境分段**：牛、熊、震荡、不同情绪阶段分别统计，避免只在单一行情有效。
- **B 模板单独验证**：B 的样本更少、换手更高，必须单独做样本外和模拟盘；不要用双模板合并收益掩盖 B 的失效。
- **禁止使用未来数据调参**：所有参数选择必须记录数据区间和版本。

### 7.7 可复现

- 回测运行记录：配置快照、`data_version`、`code_version`（git SHA）、随机种子（若使用）、`template_mode(A|B|dual)`。
- 相同输入必须得到相同输出；排序使用稳定的 `ts_code` 次序。
- 回测结果和交易明细落盘，支持重新打开和对比。
- 环境层、行业强度、龙头分都保存每日快照，支持按日复盘。

### 7.8 性能目标

- 全市场 2018 年至今的日线回测：普通笔记本电脑 5 分钟内完成（A-only 或 B-only）；双模板可放宽到 8 分钟。
- 每日增量任务（数据已同步）：3 分钟内完成。
- 若超出目标，优先优化特征预计算和 DuckDB 查询，不牺牲时点正确性。

## 8. 实盘运行

### 8.1 每日任务

调度时间：每个交易日 17:00（Asia/Shanghai，可配置）。执行链：

```
交易日检查 → 增量同步 → 数据质量闸门 → 趋势/宽度/情绪计算
→ 行业强度/龙头分 → 选股（A/B）→ 买点 → 止损 → 仓位 → 止盈
→ 风控 → 落库 → 报告 → 通知
```

- 数据未就绪时每 10 分钟重试，默认 19:00 后标记失败并告警。
- 非交易日不运行；节假日按 `trade_cal` 判断。
- 任务结束后记录耗时、数据版本、策略版本、情绪阶段、候选数量、A/B 计划数量和失败原因。

### 8.2 手动触发与幂等

- 看板按钮和命令行均调用同一任务服务。
- 参数：交易日、执行范围（`full` / `screener_only`）、模板模式（`A` / `B` / `dual`）、是否强制覆盖。
- 幂等键：`(trade_date, scope, template_mode, strategy_version)`。
- 已成功且未强制时，直接返回已有结果；强制重跑覆盖当天结果，不追加重复记录。
- 同日重复运行不得产生重复计划、重复信号或重复持仓调整。

### 8.3 任务可靠性与告警

- 单飞锁：同一交易日、同一范围只允许一个任务运行；`template_mode` 是任务参数，不单独加锁。
- 任务状态：`QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`。
- 失败自动重试（默认 3 次，指数退避）；仍失败则告警。
- 告警渠道：邮件 SMTP 和通用 Webhook（可配置，默认关闭）。
- 看板显示：上次成功时间、数据新鲜度、运行中任务、错误详情和重试按钮。
- 情绪阶段切换、B 数据降级、模板不可用等事件也要在任务日志和报告中记录。

### 8.4 每日报告

报告同时生成 HTML 和 Markdown，保存在 `reports/YYYY-MM-DD/`，可选邮件推送。内容包括：

- 市场环境：趋势档、情绪阶段、风险系数、A/B 模板可用性。
- 情绪指标：涨停/跌停家数、最高连板、晋级率、炸板率、昨日涨停红盘率/溢价。
- 主线行业：强度排名前 3–5、持续性、行业宽度、涨停数。
- 数据状态：最新交易日、覆盖率、质量检查结果、数据降级说明。
- 候选池：按模板 A/B 分组，龙头排名、评分、理由、关键指标。
- 次日交易计划：模板标签、触发价/区间、止损、股数、市值、风险金额、目标位、有效期、失效条件。
- 持仓与预警：当前止损、距止损距离、R 倍数、目标触发、时间止损、计划偏离、情绪阶段变化。
- 风险状态：持仓数、A/B 名额、总仓位、heat、回撤、熔断状态。
- 当日变化：新增计划、取消计划、到期计划、持仓调整、阶段切换动作。

### 8.5 成交与持仓跟踪

1. 用户确认计划：表示接受建议，计划仍为 `PENDING_ENTRY`，并记录确认时间。
2. 用户录入成交（手动或 CSV）：价格、数量、时间、费用、来源；成交后计划进入 `OPEN`。
3. 系统计算持仓成本、可用数量（T+1）、初始 R、当前止损、模板标签。
4. 每日任务更新移动止损、目标触发、时间止损和预警；B 模板额外检查情绪阶段和板块炸板率。
5. 用户录入卖出成交：更新剩余数量、已实现 R、费用和复盘标签。
6. 全部卖出后：`CLOSED`。
7. 与券商适配器对账：股数、成本、现金差异高亮，需用户确认。

- 部分成交按实际成交数量记账；未成交部分由用户决定继续等待或取消；计划在首次成交后进入 `OPEN`。
- 所有人工修改保留修改前/后值和操作者，写入审计日志。
- 计划执行偏差（未按触发价、未按计划股数、提前/延后退出）必须记录原因，供短板诊断。

### 8.6 券商适配器

统一只读接口：

```text
BrokerAdapter
  get_cash() -> CashSnapshot
  get_positions() -> list[BrokerPosition]
  get_trades(since: date) -> list[BrokerTrade]
```

v1 实现：

- `ManualAdapter`：用户在看板手动录入成交和持仓。
- `CsvAdapter`：导入券商导出的成交/持仓 CSV，做字段映射和去重。

后续实现：

- `QmtAdapter`：miniQMT / xtquant 读取持仓和成交。
- `PtradeAdapter`：Ptrade 环境内读取账户信息。

约束：

- v1 适配器**只读**，不包含 `place_order` 方法。
- 券商接口不可用时，手动/CSV 始终可用。
- 若券商只提供持仓快照、不提供成交明细，适配器可只实现 `get_positions` / `get_cash`，成交由用户录入。
- 适配器只负责读取和标准化，不参与交易决策。

### 8.7 安全边界

- v1 绝不自动下单。
- 所有写操作（确认计划、录入成交、修改持仓、取消计划）必须由用户显式操作。
- 服务默认只监听 `127.0.0.1`；局域网访问必须启用认证和 HTTPS 反向代理。
- token、密码、券商凭证只从环境变量或本地密钥文件读取，不写入日志、不提交 git。
- 审计日志记录所有人工操作。

  - `industry`：行业强度权重、选取数量、持续性；
  - `leader`：龙头分权重、跟风排除规则；
  - `template_a`：A 的股票池、条件、买点、止损、止盈、风险比例；
  - `template_b`：B 的股票池、条件、买点、止损、止盈、风险比例；
  - `switching`：阶段到模板可用性和风险系数的映射。
- 配置使用 Pydantic 校验，非法配置启动失败并给出字段级错误。
- `.env` 存放 Tushare token、SMTP 密码、登录密钥；`.env.example` 提供模板。
- 配置变更记录版本和修改时间；交易计划保存生成时的配置快照哈希。

### 10.4 错误处理原则

- **失败关闭（fail closed）**：数据质量不通过、关键配置缺失、账户状态不一致、情绪指标不完整时，不生成信号，而不是用猜测值继续。
- **类型化异常**：数据错误、配置错误、风控拒绝、券商读取失败分别使用不同异常类型，API 返回稳定错误码和可读中文信息。
- **事务边界**：一次任务的结果（环境快照、候选、计划、风控决定、任务状态）在同一事务中提交；失败不留下半套计划。
- **幂等重跑**：任何写操作都支持同一幂等键重复执行，覆盖而不是追加。
- **不吞异常**：后台任务捕获异常后必须记录堆栈、更新任务状态并告警，禁止静默失败。
- **审计可追溯**：人工修改保留修改前后值；自动决策保留输入版本和理由。

### 10.5 日志与可观测性

- 结构化日志（JSON），包含时间、级别、任务 ID、交易日、模板、情绪阶段、模块、耗时。
- 任务日志按日期切分并保留最近 90 天。
- 关键指标：任务耗时、候选数量、A/B 计划数量、情绪阶段、数据覆盖率、同步失败次数、回测耗时。
- 看板展示数据新鲜度和最近任务状态，避免“任务悄悄失败”。

### 10.6 部署与备份

- 本地单机运行：后端 FastAPI + 前端静态文件；可用 systemd 或 Docker Compose 守护。
- 时区固定 Asia/Shanghai；服务器时间需与北京时间同步。
- SQLite 每日备份，保留 30 天；原始 Parquet 不删除。
- 升级前备份 `data/app.db` 和配置；数据库迁移使用 Alembic。

## 11. 测试策略

### 11.1 单元测试

- 每个模块的确定性输入/输出测试，覆盖正常、边界和失败场景。
- 指标计算（MA、ATR、相对强度、市场宽度、涨停/连板/炸板/晋级）与手工计算样例比对。
- 情绪阶段分类：为每个阶段构造黄金样例；验证 2 日确认和冲突时取防守阶段。
- A/B 切换：验证每个阶段下模板可用性、风险系数、名额上限。
- 仓位计算：整手取整、最小股数、单票上限、现金保留、heat 上限、行业/相关性约束、A/B 风险比例。
- 止损止盈优先级、分批股数取整、费用计算、A/B 时间止损。
- 风控：熔断、环境系数、模板不可用、重复计划、数据版本不一致。

### 11.2 前视偏差测试

- 取某历史日期 T，用“截至 T 的数据”和“完整数据”分别计算 T 日信号，结果必须完全一致。
- 检查所有特征函数不引用未来行；用静态检查和运行时断言双重防护。
- 回测股票池包含退市股票；断言不使用当前股票列表。
- 行业成分、情绪指标、龙头排名均按 T 日时点生成；断言不使用未来成分/未来涨停数据。
- 阶段切换使用 T 日收盘确认，T+1 生效；不得用 T+1 数据反推 T 日阶段。

### 11.3 回测不变量

- 现金始终 ≥0。
- 股数始终为 100 的整数倍。
- 买入当日不可卖出（T+1）。
- 持仓数量、单票市值、总仓位、heat 不超过配置上限。
- B 模板占用的名额不超过 2，A+B 合计不超过 3。
- 费用始终非负；成交价在当日高低价范围内（除滑点调整外）。
- 同一天止损与止盈同时触发时按止损处理。
- 相同输入重复运行结果一致（快照测试）。

### 11.4 数据质量测试

- 构造缺失交易日、重复行、OHLC 违规、复权因子异常、涨跌停不一致等脏数据，验证闸门能拦截并给出明确原因。
- 构造情绪指标缺失、行业映射缺失、`limit_list_d` 不可用等场景，验证 B 模板被标记降级或禁用。
- 验证增量同步的幂等性：重复拉取同一交易日不产生重复数据。
- 验证数据降级标注：接口不可用时报告必须显式说明。

### 11.5 集成测试

- 构造一个小型合成市场（如 20 只股票、2 年日线），包含涨停、跌停、停牌、除权、退市、板块轮动、情绪周期切换等事件。
- 端到端运行“环境 → 选股 → 五模块 → 风控 → 回测”，分别验证 A-only、B-only、双模板。
- API 契约测试：请求/响应模型、错误码、分页和筛选。
- 前端冒烟：运行任务 → 查看情绪阶段/行业 → 查看 A/B 计划 → 确认 → 录入成交 → 持仓出现 → 录入卖出 → 计划关闭。

### 11.6 性能测试

- 全市场 2018 年至今回测在目标时间内完成。
- 每日增量任务在目标时间内完成。
- 对特征计算、情绪指标、行业/龙头排名和 DuckDB 查询做基准测试，防止性能回退。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Tushare 接口权限不足或限流 | 数据不完整、B 模板不可用 | M1 先做权限预检；本地缓存和增量同步；缺失权限显式降级并标注；B 可禁用 |
| 情绪指标失真或被操纵 | 阶段误判、模板切换错误 | 多指标共振、2 日确认、冲突取防守；回测分阶段验证 |
| 行业分类/成分股未来函数 | 方向层回测虚高 | 使用历史成分；不可用时标记分类降级；回测报告提示偏差 |
| B 模板执行敏感、容量小 | 回测与实盘差异大 | 保守成交假设；B 单独回测和模拟盘；高滑点假设；不自动下单 |
| 数据未来函数或幸存者偏差 | 回测虚高、实盘失效 | 时点股票池、后复权、截断测试、包含退市股票 |
| 参数过拟合 | 样本外表现差 | 滚动样本外、参数敏感性、消融对比、限制调参次数 |
| 默认选股规则不适合用户 | 选股质量差 | 选股作为可替换插件；用回测对比后切换；不硬编码到其他模块 |
| 券商接口不可得 | 无法自动同步持仓 | 手动/CSV 兜底；适配器接口隔离；QMT/Ptrade 后续接入 |
| 每日任务失败或未运行 | 错过计划、持仓失控 | 任务状态、告警、重试、看板数据新鲜度、单飞锁 |
| 回撤扩大 | 资金损失 | 单笔风险上限、组合 heat、回撤熔断、暂停新开仓 |
| 人工执行偏离计划 | 实际结果与回测不一致 | 记录成交偏差、复盘标签、执行质量统计 |
| 本地数据丢失 | 历史与状态丢失 | SQLite 每日备份、原始 Parquet 保留、配置版本化 |
| 依赖库或接口变更 | 系统不可用 | 固定依赖版本、适配器隔离、集成测试 |

## 14. 后续演进

以下内容明确不在 v1 范围内，但架构预留扩展点：

1. **用户自定义选股策略（首要）**：按 `ScreenerStrategy` 协议新增策略文件，配置版本化；同一时间段与默认双模板对比回测。
2. **B 模板盘中执行**：在 Tushare 实时/分钟权限可用时，监控分歧低吸、回踩确认、封板/炸板，推送到看板/邮件/Webhook；仍由用户人工下单。
3. **券商只读同步**：QMT（xtquant）或 Ptrade 适配器读取持仓和成交，替换手动/CSV。
4. **受控自动下单（需单独设计与审批）**：明确风控、熔断、人工确认、kill switch、审计和回放；不属于 v1。
5. **更多选股因子**：基本面、资金面、事件驱动、龙虎榜、北向资金；以独立因子插件接入，不污染五模块边界。
6. **行业/题材数据升级**：更完整的历史成分、概念板块、题材热度；提升方向层和 B 模板质量。
7. **多策略/多账户**：策略组合与资金分配；需要扩展账户和风控模型。
8. **通知渠道**：企业微信、飞书、Telegram 等 Webhook。
9. **移动端适配**：看板响应式优化或独立移动页面。
10. **组合优化**：在固定风险法之上加入相关性约束和资金分配优化；需回测验证。
11. **每日/每周短板报告自动化**：把第 3.7 节的诊断指标固化为定时报告。

### 15.2 A 股规则假设

- 交易时间：09:30–11:30，13:00–15:00（Asia/Shanghai）。
- T+1：买入当日不可卖出。
- 整手：买入 100 股整数倍；卖出可卖零股（系统默认仍按整手计算分批）。
- 涨跌幅：以 `stk_limit` 为准；接口不可用时按板块和状态推导：主板 10%，主板 ST 5%，创业板/科创板 20%（其 ST 股票 20%），北交所 30%（默认不参与）。上市初期无涨跌幅限制的股票已被 120 个交易日过滤。
- 费用：佣金 0.025%（最低 5 元）、卖出印花税 0.05%、过户费 0.001%，均按当前常见口径，可在配置中调整。
- 节假日：以 `trade_cal` 为准。
- 除权除息：按 `adj_factor` 和分红送转调整；回测与实盘跟踪一致。

### 15.3 默认选股规则的地位

第 5.1 节的双模板规则是**让管线先跑通的默认基线**，不是系统对用户的投资建议，也不是不可更改的核心逻辑。用户可以用自己的选股策略整体替换，只需满足 `Candidate` 契约。替换后必须用同一套回测、样本外和消融分析验证，再决定是否用于实盘。

双模板的定位：

- 模板 A 是核心，适合日线、T+1 和人工执行；
- 模板 B 是卫星，收益弹性更高，但对数据、执行和情绪判断要求更高；
- A/B 都必须单独回测、单独模拟盘，不能只看合并收益。

### 15.5 选股方法调研摘要（设计依据）

本系统的 A/B 双模板不是对某一位成功投资者的复制，而是从公开访谈、券商研报和量化研究中提取可回测的共性。

| 流派 | 代表 | 核心方法 | 在本系统中的处理 |
|---|---|---|---|
| 价值/长期 | 段永平、林园、但斌、张坤、邱国鹭、王富济 | 好生意、护城河、垄断+成瘾、ROE/自由现金流、便宜的好公司、长期集中 | v1 不采用；留作独立长线策略 |
| 逆向/赔率 | 冯柳 | 弱者体系、赔率优先、杀估值>杀业绩>杀逻辑 | v1 仅保留为后续研究方向 |
| 产业趋势/成长 | 邓晓峰、葛卫东 | 好行业好公司好价格、产业周期、稀缺性、跟势不跟人 | 转化为方向层（行业强度）+ 龙头 |
| 短线情绪/龙头 | 赵老哥、炒股养家、瑞鹤仙 | 主线、龙头、情绪周期、买在分歧卖在一致、严格止损 | 转化为环境层（情绪阶段）+ 模板 B |
| 量化多因子 | 幻方、九坤等 | 分散持仓、行业/市值中性、短周期反转/小市值 | 与 3 只集中持仓不同，仅借鉴因子和回测方法 |

**调研结论：**

- 成功者没有统一的选股法；共性集中在四件事：**环境（什么时候做）、主线（做哪个方向）、龙头（做哪只）、纪律（怎么死）**。
- 模板 A 取“主线趋势回踩”，覆盖中线、日线可执行、人工可操作的部分。
- 模板 B 取“情绪龙头”，覆盖短线弹性，但必须依赖涨跌停/连板/炸板数据和严格执行。
- 价值/长期和逆向赔率需要财务、估值和更长持有期，不与 v1 的短中线系统混用。
- 公开言论不等于实际策略；案例存在严重幸存者偏差；打板/龙头策略对执行、成本、数据质量和市场阶段高度敏感。
