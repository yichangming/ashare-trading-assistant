# 验收标准与测试矩阵

> “测试通过”只证明软件行为符合规则，不证明策略盈利。软件功能与策略有效性分开报告。
> demo 数据/绩效不得作为策略有效证据。

## 2. 必测边界

- 计划过期、触发但未成交、部分成交、重复成交导入、撤单失败。
- 行情中断/最新数据缺失/账户过期/服务重启。
- 同日止损与止盈、跳空穿越止损、跌停无法卖、停牌延迟。
- 除权除息、复权/未复权价格转换、公司行动。
- 多策略同股合并、行业/相关性/heat/现金/单票上限。
- 回测未来函数：截断到 T 与全量在 T 的决策一致。
- 退市股、停牌股、涨跌停不可成交、B2 未完成 bar 不使用。

## 3. 测试层次

1. **单元**：策略检测/确认/失效/重置；指标；仓位/止损/止盈/风控。
2. **契约**：策略接口、数据 provider、broker、CSV、通知、API 模型。
3. **集成**：日线盘后 → 计划 → 成交导入 → 持仓 → 次日监控 → 退出。
4. **端到端**：Web 登录 → 运行任务 → 查看机会/持仓 → 录入成交 → 报告/通知；demo 切换。
5. **回测不变量**：现金非负、整手、T+1、限额、费用非负、同日止损优先、可复现。
6. **性能**：日线增量任务、回测目标时间；分钟池轮询不超限。

## 4. 交付物

- 代码（含测试、配置、模板、迁移、Docker）。
- 架构文档、策略规则、参数表、数据接入、部署手册、测试报告、外部权限/成本、已知限制。
- 运行方式：`uv run` CLI/API/Web；Docker Compose。
- 默认不含真实交易下单路径。

## 5. 策略有效性门槛（research_defaults_v1）

- 每个策略/子模式至少：样本外区间、滚动验证、成本敏感性、环境分层、模拟盘/纸面跟踪。
- 未达到门槛 → `research`/`paper`；不得标为 `live_candidate`。
- 报告分别给出“软件验收结果”和“策略绩效结果”；后者不能由前者替代。
- 样本不足（如 B2 分钟数据、F 事件）明确标注，不伪造完整回测。
