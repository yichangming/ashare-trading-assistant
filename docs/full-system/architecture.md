# A 股个人交易辅助系统 — 完整系统架构（v2）

> 状态：实现基线（2026-11-01）
> 适用：单用户、本地/单机部署、东方财富证券人工交易
> 原则：不自动下单；不把盘后数据伪装成实时数据；不把测试通过等同于策略盈利。

## 1. 现有实现与差距

现有仓库已实现 M1/M2：

- Tushare 日线同步、manifest、Parquet/DuckDB、质量闸门、点时股票池、特征；
- 情绪/趋势/行业/龙头、双模板 A/B 选股、买点/止损/仓位/止盈/组合风控、管线、CLI；
- 761+ 离线测试；2018-2026 日线数据已在本机 `backend/data/`（gitignored）。

本次 v2 在此基础上扩展，不重写数据层和已正确的模块：

| 能力 | 现状 | v2 需要 |
|---|---|---|
| 策略 | A/B 双模板（简化） | A–F 六类策略及 B1/B2、C1/C2 等子模式 |
| 行情判断 | 趋势/情绪/宽度/行业 | 四维判断 + 分策略权限 + 全局风险/数据开关 |
| 计划状态机 | DRAFT/PENDING/OPEN/CLOSED 等 | 观察/待触发/确认/待执行/部分成交/成交/失效/取消/过期 |
| 账户 | JSON 账户文件 | SQLite 账户、持仓、成交、CSV 导入、对账、审计、公司行动 |
| 回测 | 无 | 日线/5 分钟回放、成本、T+1、停牌/涨跌停/退市、指标、归因 |
| 调度 | 无 | APScheduler、幂等、防重入、断点恢复、盘后/盘中任务 |
| Web | 无 | FastAPI + 响应式中文看板、8 个页面、SSE、通知中心 |
| 事件 | 无 | 四类事件、原文/来源/时间/修订/撤回、F 策略、人工核验 |
| 部署 | CLI + README | Docker Compose/等价、迁移、备份恢复、HTTPS/认证说明 |

## 2. 架构

```
┌──────────────────────────────────────────────────────────────────┐
│ Web / API：FastAPI + Jinja2/HTMX + ECharts + SSE                  │
│ 今日总览 | 机会 | 持仓 | 计划/成交 | 报告 | 回测 | 通知 | 设置   │
├──────────────────────────────────────────────────────────────────┤
│ 应用服务：每日任务、盘中监控、报告、通知、账户/成交、回测          │
│ APScheduler（后台进程内，页面关闭不停止）                         │
├──────────────────────────────────────────────────────────────────┤
│ 决策层：行情判断 → 策略权限 → A-F 选股 → 买点 → 止损 → 仓位      │
│         → 止盈 → 组合风控（统一决策逻辑，回测/实盘共用）           │
├──────────────────────────────────────────────────────────────────┤
│ 领域层：MarketRegime / Candidate / TradePlan / Position / Execution│
│         Account / Event / Notification / JobRun / BacktestRun      │
├──────────────────────────────────────────────────────────────────┤
│ 数据层：Tushare 日线/5分钟/事件 → Parquet + DuckDB                 │
│         运营状态 → SQLite（SQLAlchemy + Alembic）                 │
│         报告/回测产物 → 文件；本地备份                            │
└──────────────────────────────────────────────────────────────────┘
```

### 2.1 模块边界

- `app/data/`：数据源适配、同步、清洗、质量、provider。已有代码保留。
- `app/indicators/`、`app/regime/`：特征、趋势、宽度、波动、情绪、行业、龙头。已有代码扩展。
- `app/strategies/`：A–F 策略，纯函数/确定性；输出 `Candidate` 与策略证据。
- `app/planning/`：统一买点/止损/仓位/止盈；按策略规则分派。
- `app/risk/`：组合风控、权限、全局风险开关。
- `app/portfolio/`：账户、持仓、成交、CSV、对账、公司行动、审计。
- `app/events/`：事件入库、核验、修订/撤回、F 策略输入。
- `app/backtest/`：回放、模拟撮合、指标、归因、walk-forward、消融。
- `app/jobs/`：调度、任务锁、重试、报告、通知。
- `app/api/`：FastAPI 路由、认证、SSE、表单。
- `app/web/`：Jinja2 模板与静态资源。
- `app/db/`：SQLAlchemy 模型、会话、仓储、迁移。

### 2.2 进程与持久化

- 单进程 FastAPI + 进程内 APScheduler；页面关闭不影响后台任务。
- 生产可用 systemd/Docker Compose 守护；任务状态、计划、持仓、通知全部落 SQLite。
- 任务使用 `job_runs` 唯一键 `(trade_date, scope, template/strategy_mode)` + 行锁/单飞标记；重启后恢复未完成任务。
- 行情 Parquet 不变；SQLite 每日备份；报告/回测产物保留策略可配置。
- 所有时间使用 `Asia/Shanghai`；交易日历以 `trade_cal` 为准。

## 3. 数据流

### 3.1 盘后

```
交易日检查 → 增量同步日线/事件 → 质量闸门（失败关闭）
→ 特征/点时股票池 → 四维行情 → 分策略权限
→ A-F 候选 → 统一买点/止损/仓位/止盈 → 组合风控
→ 计划落库 → 通知 → 日报 → Web/API
```

### 3.2 盘中

```
账户/持仓新鲜度检查 → 行情健康检查（实时或5分钟）
→ 持仓保护线/硬风险/时间/事件检查
→ B2（5分钟）与 C1/C2 确认；A/D/E 只在日线确认
→ 信号/预警入通知 → 人工执行 → 成交导入
```

- 盘中只使用当时已完成的 5 分钟 K 线或实时快照；不把日线/收盘后数据当实时。
- 浏览器关闭后监控继续；不承诺锁屏/离线送达。

### 3.3 成交与持仓

```
计划 PENDING_EXECUTION → 人工下单 → 成交 CSV/手工录入
→ Execution（部分成交多行）→ Position/Lot 更新
→ 资金/风险额度释放或占用 → 审计
```

- 卖出通知 ≠ 成交；只有确认成交后才释放资金/风险。
- 部分成交按实际数量；未成交部分继续等待或取消。

## 4. 统一状态机

| 状态 | 含义 | 进入条件 |
|---|---|---|
| `OBSERVING` | 观察形态，尚未触发 | 策略发现候选/结构 |
| `PENDING_TRIGGER` | 等待价格确认/冻结条件 | 观察条件成立 |
| `CONFIRMED` | 确认信号已产生 | 收盘/5分钟确认 |
| `PENDING_EXECUTION` | 计划有效，等待人工执行 | 风控通过 |
| `PARTIAL_FILL` | 部分成交 | 成交数量 < 计划 |
| `OPEN` | 已成交持仓 | 成交确认 |
| `CLOSED` | 全部退出 | 止损/止盈/时间/事件/人工 |
| `CANCELLED` | 主动取消 | 用户/环境/模板 |
| `EXPIRED` | 有效期结束 | 到期未触发 |
| `INVALIDATED` | 结构失效 | 破位/条件破坏 |
| `REJECTED` | 风控拒绝 | 硬约束失败 |
| `DRAFT` | 管线已生成未风控 | 内部 |

- 计划字段：策略/子模式、信号时间、数据时间、确认参考价 P、最高接受价、执行价格区间、初始止损、股数、R、目标、有效期、取消原因、策略/数据/代码版本。
- 规则：`max_acceptable = P + min(P×1%, ATR14×0.25)`；默认执行价在 `[P, max_acceptable]`；超出暂停执行并复核；结构失效/到期取消；价格按标的精度、股数按 100 股。
- 目标可靠时扣费后潜在收益/计划损失 ≥1.5；无可靠目标时标记 `target_unknown`，不编造。

## 5. 行情判断与权限

四个独立维度：

1. 趋势：指数 000985.CSI（回退 000300.SH）相对 MA20/MA60、MA20 斜率。
2. 宽度：可交易股票站上 MA20 比例、5 日变化。
3. 波动/流动性：20 日波动历史分位、下跌扩散、成交额异常。
4. 短线情绪：涨停/跌停、炸板率、晋级率、昨日涨停红盘率/溢价、最高连板。

每个维度有独立阈值、升级/降级边界和 2 日确认；冲突取更防守。对 A–F 分别输出 `normal/reduced/paused`，不共享一个开关。全局风险开关处理极端风险/数据故障：

- `pause_new`：暂停新增；存量按策略管理。
- `reduce`：建议减仓（人工确认）。
- `clear`：建议清仓（硬风险优先，人工确认/执行）。
- 数据缺失/质量失败 → 暂停新增，明确标注“数据不可用”，不解释为安全。

## 6. 账户与风险

- 账户模式：`real` / `paper` / `demo`；demo 必须显著标识，绩效不能作为策略证据。
- 真实账户未设置资金/可接受回撤时：研究和模拟可运行；真实账户股数显示“风险配置未完成”，不生成假装适用的数量。
- 同一股票多策略合并持仓与风险；保留每笔来源策略/子模式、原始评分和主策略。
- 加仓：新有效买点 + 原持仓无浮亏 + 总风险合格；每周期最多 2 次、每次 ≤ 首次实际买入 50%；A/C/F 支持，B/D/E 默认关闭；不降保护线。
- 止损：硬风险退出、收盘结构失效、移动、时间、事件；风险优先；保护线只收紧（除权调整除外）。
- 止盈：A/C 分批+趋势；B/D 及时兑现/时间；E 上沿；F 价格+事件。
- 退出优先于新增；硬风险清仓优先于加仓。

## 7. 回测

- 与实盘共用策略/买点/止损/仓位/止盈/风控代码；只替换时钟、数据 provider 和模拟 broker。
- 日线：T 日收盘生成，T+1 起成交；停牌/涨跌停/退市/跳空保守处理。
- 5 分钟：只用已完成 bar；B2 信号有效 10 分钟；无法判断日内止损/止盈先后时按止损优先。
- 费用：佣金、印花税、过户费、滑点；A/B 滑点可不同。
- 指标：净收益、年化、回撤、Sharpe/Sortino/Calmar、胜率、盈亏比、期望 R、换手、成交率、持仓时间、资金占用、基准。
- 每个策略/子模式独立统计；共享资金组合结果；walk-forward、样本外、消融、成本敏感性。
- 分钟/事件数据不足时：只回测可用区间，输出缺失说明；不允许用日线伪造盘中 B2 或事件全文。
- demo 数据单独标记，绩效不作为有效性证据。

## 8. Web 与通知

- 8 个页面：今日总览、六类策略机会、持仓监控、计划与成交、每日报告、回测/模拟、通知中心、设置与运行健康。
- 响应式中文页面；SSE 推送任务/通知；连接状态和数据时间可见；可选声音。
- 通知：风险优先、去重、确认/未处理；站内通知中心；不接微信/Server酱。
- 普通研究信号与真实持仓风险明显区分。

## 9. 安全与部署

- 单用户登录；密码哈希（scrypt/Argon2）+ 服务端会话；无通用默认密码。
- 默认仅监听 127.0.0.1；局域网/HTTPS 需显式配置反向代理和认证。
- 密钥只从环境变量/本地密钥文件读取；日志脱敏；`.env`/`data/` 不入库。
- Docker Compose（或 systemd）部署；Alembic 迁移；SQLite 每日备份；恢复手册。
- 不自动下单；不接真实交易接口；所有买卖人工执行。

## 10. 外部数据能力（已实测，2026-11-01）

| 数据 | 接口 | 状态 | 时延/限制 | 用途 |
|---|---|---|---|---|
| 日线/复权/每日指标/涨跌停/停牌/指数 | `daily` 等 | 可用 | 盘后更新；按日 | A–F 日线 |
| 5 分钟 | `stk_mins` | 可用 | **1 次/分钟/接口**；完成 bar；49 根/日 | B2、盘中 |
| 1 分钟 | `stk_mins` | 受限/未稳定 | 同接口限频 | 暂不作为核心 |
| 指数 5 分钟 | `index_mins` | 接口名不可用 | — | 用日线/实时指数替代 |
| 实时报价 | `ts.realtime_quote` | 休市返回空 | 盘中时延未验证 | 盘中辅助，必须健康检查 |
| 实时 K 线 | `rt_k` | 无权限 | — | 不使用 |
| 业绩预告/快报/财报 | `forecast_vip`/`express_vip`/`income_vip` | 可用 | 按报告期/公告日 | F |
| 回购/股东增减持 | `repurchase`/`stk_holdertrade` | 可用 | 按公告日区间 | F |

外部成本：Tushare 积分/权限由用户账户决定；不引入微信/Server酱；不产生交易接口费用。

## 11. 非目标

- 不自动下单、不接东方财富交易 API。
- 不做多用户/SaaS、移动 App、微信推送。
- 不把未验证策略包装为盈利建议；research/paper 状态必须可见。
